### The e2e failure was a real product defect, not a flaky test

`Recent Messages › lists what was generated and reopens it` failed with the UI showing:

> The studio API could not be reached. Check that the backend is running on port 8000.

The backend was running. The cause:

```python
app.add_middleware(CORSMiddleware, ...)   # registered first
@app.middleware("http")                   # registered second
async def request_context(...): ...
```

Starlette's `add_middleware` **inserts at the front**, so the *last* registration is the
outermost. `request_context` therefore wrapped `CORSMiddleware`, and every response it
short-circuits — `400 INVALID_CONTENT_LENGTH`, `413 REQUEST_TOO_LARGE`,
`429 RATE_LIMIT_EXCEEDED` — bypassed CORS entirely. A response with no
`Access-Control-Allow-Origin` is discarded by the browser and surfaces to `fetch()` as a
bare network error, indistinguishable from a dead server.

Reproduced directly before fixing:

```
0 200 ACAO= http://localhost:3000
3 429 ACAO= None          ← browser discards this
OPTIONS -> 429 ACAO= None ← preflight throttled too, so every POST then fails
```

Consequences beyond the flaky test: a tester who trips the 600/minute limit is told to
restart a healthy server; an oversized Excel upload reports the same thing instead of "your
file is too large"; and once the limit is near, CORS preflights are themselves throttled, so
every browser `POST` fails at preflight with an error no one can explain.

## 2. Work implemented

### Phase A — the defect and its neighbours

- **CORS is now the outermost middleware.** Registration moved below every other middleware,
  with a comment recording why order is the whole fix.
- **Genuine CORS preflights are exempt from the rate limiter.** A preflight is browser
  overhead the caller never chose to send; throttling it breaks legitimate browser clients
  and defends nothing, because a non-browser client never sends one. Only requests carrying
  both `Origin` and `Access-Control-Request-Method` are exempt — a bare `OPTIONS` still counts.
- **The frontend distinguishes 429 from unreachable.** `studio-api.ts` maps a throttled
  response to "Too many requests… wait N seconds", reading `Retry-After`.
- **`backend/config/mx/xsd/official/`** now exists with a README explaining the naming
  convention and what changes when a licensed schema is dropped in. `.gitignore` excludes
  `*.xsd` there so a licensed file cannot be committed by accident.

### Phase B — MX import and round trip (priority 1)

`backend/app/studio/mx/parser.py` (576 lines) reads an ISO 20022 document back into
canonical `ElementInput` values — the same type the JSON API and the Excel importer produce.
It is the exact inverse of the composer and does nothing else: the parsed values are handed
straight to `StudioService.generate`, so an imported message is regenerated by the code that
generates every other message. There is no import-only composer, validator or renderer.

- **Identification is by namespace**, never by root tag or a caller-supplied type — the
  namespace is the only self-describing part of an ISO 20022 document, and trusting a
  caller would let a mislabelled file be parsed against the wrong specification.
- **Occurrence numbering is inverted exactly.** The composer threads one occurrence index
  down through each repeatable container into its non-repeatable descendants; the parser
  reassigns the same index walking back up. Without this, every repeat collapses onto the
  first one's values and the loss is invisible in the output.
- **Three input shapes are accepted:** a wrapped payload, a bare `Document`, and an `AppHdr`
  and `Document` downloaded separately and pasted one after the other — which is two sibling
  roots and therefore not well-formed XML on its own, so it is wrapped before parsing.
- **Nothing is silently dropped.** Nine named refusals, each with an `expected` and a
  `suggestion`: unknown element, disallowed repeat, empty element, text in a container,
  children on a leaf, foreign namespace, header/document mismatch, unidentifiable document,
  and the nested-repeat case the flat occurrence model cannot represent.

`POST /api/v1/messages/import` returns the canonical elements, the recovered envelope, the
separated import issues **and** the regenerated `GenerateResult`. Import problems are folded
into the returned validation as well as listed separately, so a partial import can never be
mistaken for a faithful one.

**In the browser:** import lives on **step 1** of the Create Message wizard, before a message
is chosen — because the document names itself, and asking a tester to pick `sese.023` before
pasting a `sese.025` only sets them up to be contradicted. Importing skips steps 1–4 and
lands in the builder with every value loaded, ready to edit → validate → regenerate. The
Validate screen gained a matching "An existing MX message" mode.

### Phase C — MX cancellation/modification lifecycle (priority 2)

Four YAML files. **Zero lines of Python.**

| Message | Root | Purpose |
|---|---|---|
| `sese.020.001.08` | `SctiesMsgCxlAdvc` | withdraws a message already sent |
| `sese.027.001.08` | `SctiesTxCxlReq` | asks the servicer to cancel an accepted transaction |
| `sese.030.001.10` | `SctiesSttlmCondsModReq` | asks to change a condition (hold/release, date, partial, linkage) |
| `sese.031.001.09` | `SctiesSttlmCondModStsAdvc` | answers the modification request |

Each gained samples, Excel template columns, Message Intelligence entries, import support
and derived-XSD validation with no code change — which is the strongest available evidence
that "a message is a specification plus values" is true and not aspirational.

Both new business rules are **configuration**: `requireOneOf: [[HldInd, ModfdSttlmDt,
PrtlSttlmInd, Lnkgs]]` on `sese.030` (a modification that requests no modification is not a
request) and `requireOneOf: [[PrcgSts]]` on `sese.031`. "A command must name what it acts on"
needed nothing at all — marking the reference `MANDATORY` in YAML is the rule.

## 6. Remaining external blockers

Nothing was fabricated to work around these. Each is recorded rather than guessed.

1. **Licensed ISO 20022 message-definition reports.** The four new lifecycle specifications
   carry an explicit `UNVERIFIED` limitation as their *first* limitation: **version number,
   message root element name and element set were modelled on the ISO 20022 idioms already
   present in this repository, not reconciled against an authoritative source.** They are
   shipped in the same honest frame the existing three use
   (`CONFIGURED_SUBSET_REQUIRES_VERIFICATION`, `authoritativeCompletenessKnown: false`,
   `capability: PARTIAL`), and a test asserts the caveat is present on the message itself so
   a reader never has to find it in a separate document. **This is the single largest
   outstanding risk in this work and should be reconciled before any external use.**
2. **Official ISO 20022 XSDs.** Still absent, so MX validation remains `SUBSET_DERIVED`. The
   drop point and its README now exist; adding files needs no code.
3. **Licensed SWIFT MT specification.** Coverage remains a repository-configured subset and
   every message still reports `PARTIAL`.
4. **The `22F::SETR` placement question** is unchanged and still needs an authoritative
   source rather than a guess.
5. **Client-specific MyStandards profiles** and **production connector contracts** — absent,
   untouched.
6. **Shared state for the rate limiter and circuit breaker** needs Redis or equivalent.
