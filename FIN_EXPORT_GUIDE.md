# FIN Export Guide

The export service separates the business text block from interface-controlled envelopes.

- `TEXT_BLOCK_ONLY`: Block 4 generated by the deterministic composer.
- `FIN_APPLICATION_MESSAGE`: configured FIN application envelope plus Block 4.
- Canonical JSON, validation JSON, validation HTML, and ZIP evidence packages.
- `RJE_SINGLE`, `RJE_BATCH`, and connector payload modes are modelled but fail closed unless an
  authorised client interchange contract is enabled.

For FIN export, sender LT, receiver address, session number, and sequence number must be explicitly
supplied in the CSRF-protected POST export body—never query parameters that access logs could
capture. The application does not fabricate network
authentication, ACK/NAK, checksums assigned by an external interface, or interface-controlled
trailers. Generated files use server-controlled names and include checksum/profile/release
metadata. Query parameters are not connector secrets and must not be used as a production routing
contract.

The current implementation supplies HTML, not PDF, validation evidence. RJE remains disabled by
default because the repository contains no approved client RJE contract.
